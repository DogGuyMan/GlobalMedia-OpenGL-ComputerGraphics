# 렌더링 시스템 흐름 리팩토링 계획안 (v2)

> 정돈: 2026-06-22 (v2 — IPassable / PassGroup 폐기 / Flat Vector 반영). *설계 의도의 충실 재진술*.
> 표기: 🟢표준이론 · 🔵Unity context7 검증 · 🟡현 엔진 대응 · 🔎해석(확인됨) · ❓열린 결정(추천 포함).

## [ROLE]
렌더링을 *그려질 대상(IRenderable) + 그릴 곳(Target/Canvas) + 그리는 단위(IPassable)* 3축으로 개편.

## [ISSUE] — 현 구조의 철학적 모순
- 현재 `CameraStage(World)`/`CameraStage(Screen)`.
- 모순: 카메라=눈, 눈은 *자기 자신을 못 봄* → "Stage(무대)"라 부르는 게 어긋남.
- 정정: 카메라가 향하는 건 **Target**, 엄밀히는 카메라 앞 **도화지 Canvas(ScreenQuad)**. "Camera/CameraStage" 명칭 폐기 → **Target(Canvas)** 중심.

---

## [핵심 개념]

### ① `IRenderable` — *그려질 대상*
- 구현체: `Mesh`(Geometry/Sprite/ScreenQuadMesh), `Skybox`, `Particle`, `Text`, `UI`.
- 메서드: `Render(Target)` — "나를 이 Canvas 에 그려라".
- 🟡 현 엔진엔 없음 (`MeshRenderer`/`PassComponent` 데이터 + `MeshPassProcessor`). → `IRenderable` 다형 통일 의도.

### ② `Target` (= Canvas) — *어디에 그리나*
- 실체: `FrameBuffer`/`Texture`. 위치는 `Transform` 으로 표현.
- 현재 모든 Frame = Window/Device/Screen 크기 동일 Texture = **Screen Coordinate Canvas**.
- 🔎 "Camera" 폐기: 카메라는 *View·Proj(Ortho/Perspective) 행렬을 가진 Target* 일 뿐.

### ③ Layer(Cull) + CullingMask — *어느 Target 이 무엇을 그리나* (🔵 Unity 정통)
- **Cull Layer (BitFlag)**: 대상에 부여하는 비트 레이어 (`Ortho`/`Perspective`/`Entity`/`UI`/`Default`…).
- **Target CullingMask**: 각 Target 이 *어떤 Cull Layer 만* 그릴지 비트마스크 선택. `Default` = 안 가리는 모든 Target 이 그림.
- 여러 Target 공존 → 🔵 Unity **Camera Stacking** (cullingMask 분담; UI/screen-space 는 항상 렌더 예외).
- 🔵 구분: Unity **Layer=가시성 culling**(cullingMask), **Tag=문자열 식별자**(culling 아님).
- 🟡 현 엔진: `Camera.CullingMask & Actor.Layer`(`Scene::Layer`: World/Screen/UI) 부분 존재 → BitFlag 일반화 대상.

### ④ `IPassable` — *그리는 단위* (★ v2 핵심 변경)
**Pass = `IPassable` 인터페이스.** 모든 Pass(Skybox/World/Particle/Screen/PostFx/ImGUI)가 이걸 구현.

> 🟡 **World Pass ≈ 현 엔진 `SceneRenderer` 의 동작과 사실상 동일.** 현 `SceneRenderer::RenderWithCamera` 가 이미:
> ① `BeginFrame(target)` → ② Light 수집 + `LightUboUploader` 업로드 → ③ `CollectFromActor`(Actor 트리 DFS 로 `MeshRenderer`→`DrawCommand` 수집) → ④ `MeshPassProcessor::SortMultiStage`(Queue Layer + Z 정렬) → ⑤ `Process`(GL draw 발행) 를 수행한다.
> → 즉 **`WorldPass : IPassable` 의 `Draw()` 본체 = 현 SceneRenderer 로직을 거의 그대로 이식**하면 된다 (출력을 자기 1-out 텍스처로 돌리는 점만 추가). 신규 작성이 아니라 *재배치*에 가깝다.

- **완전 함수형 1-in → 1-out** 🔎(확인): 모든 IPassable 은 *입력 텍스처 1장 → 자기 출력 텍스처 1장*. World/Skybox/Particle 도 *각자 텍스처*를 가짐 (누적 공유 아님).
- **순서 SSOT = `Vector<IPassable*>`** 🔎(확인): heap 포인터 링크드리스트가 아니라 **연속 메모리 Vector + 앞/뒤 *인덱스***. 이유 = **캐시 지역성** (Pass 순회는 지역성과 직결, heap 산재보다 연속 접근이 빠름).
- before/after 는 *Vector 인덱스* (포인터 아님).

```cpp
class IPassable {
public:
    virtual void    Draw() = 0;            // 입력 텍스처를 읽어 자기 출력 텍스처에 렌더
    virtual Texture GetPassResult() = 0;   // 자기 출력 텍스처 (1-out)
    int BeforeIndex = -1;                  // 입력을 가져올 앞 Pass 의 Vector 인덱스 (-1 = scene/raw)
    int AfterIndex  = -1;                  // (선택) 뒤 Pass 인덱스
};
```

#### ❓ 열린 결정 — 입력 배선 채널 (BeforePass 인덱스 vs SetBeforePass(Texture), "둘 중 하나로 정리")
`BeforeIndex`(어디서 가져올지 선언) 와 `SetBeforePass(Texture)`(그 텍스처를 주입) 는 같은 일(입력 결정)이라 하나로 정리.

| 안 | 인터페이스 | 입력 전달 | 장 | 단 |
|---|---|---|---|---|
| **A. 선언적/pull** ⭐추천 | `int BeforeIndex` + `Draw(Texture before)` | PassIterator 가 `before = (i.BeforeIndex<0 ? sceneRaw : passes[i.BeforeIndex].GetPassResult())` 해석 후 `Draw(before)` | BeforeIndex 로 *비-인접 입력*(예: blend 가 T0+T3) 유동 배선. 인덱스 기반(지역성)과 일관. setter 제거 | `void Draw()` → `Draw(Texture)` 시그니처 변경 |
| B. 명령형/push | `void Draw()` + `void SetBeforePass(Texture)` | iterator 가 `SetBeforePass(prev.GetPassResult())` 주입 후 `Draw()` | `void Draw()` 유지, 단순 | 입력=직전(i-1) 순차만, 비-인접 배선 어려움. BeforeIndex 폐기 |

→ **추천 A** (인덱스 선언 유지 = 유동 배선 + 지역성, setter 폐기). `void Draw()` 를 `Draw(Texture)` 로 한 칸 양보. *확정은 사용자.*

### ⑤ `PassIterator` — *Render Hierarchy 의 구현* (★ v2: PassGroup 폐기, Flat)
- **PassGroup + 템플릿메서드 폐기.** Pass 를 **Flat** 하게.
- `PassIterator` 가 **`Vector<IPassable*>` 를 직접 루프**:
  ```
  for (i = 0; i < passes.size(); ++i)
      passes[i].Draw( resolveInput(passes[i].BeforeIndex) );   // (안 A 기준)
  최종 = passes.back().GetPassResult();   // 화면 출력
  ```
- **Scene Hierarchy → Render Hierarchy**: 매 프레임 Scene 트리로부터 Vector 재구축(교환). PassIterator 가 그 추상의 구현.
- 순서를 *유동 배치* = Vector 에 Pass 를 원하는 순서로 담음 (PassGroup 계층 없이 평면).

## [데이터 흐름] — PassGroup 없이 Flat 체인

각 Pass 가 1-in-1-out 이므로, 체인은 **Vector 순서 + BeforeIndex 배선**으로 표현 (Tn = 각 Pass 의 GetPassResult):

```
passes: [ Skybox, World, Particle, Screen, PostFx:Sharpening, PostFx:Bloom, PostFx:Fog, ImGUI ]
          │
  idx 0   Skybox   .Draw(sceneRaw)         → T0
  idx 1   World    .Draw(T0?)              → T1     (BeforeIndex 로 입력 지정)
  ...
  idx k   PostFx:Bloom .Draw(T_{k-1})      → Tk
  idx n   ImGUI    .Draw(T_{n-1})          → Tn  → 화면
```
- 구 PostFx 체인(T1→T2→…)이 **PassGroup 반복 대신 Flat Pass[] + BeforeIndex 배선**으로 단순화.
- 비-인접 입력(안 A): 예) 합성 Pass.BeforeIndex 둘 이상 필요 시 확장 여지 (현재 단일 BeforeIndex; 다중 입력은 후속).

## [Pass 내부 2단] (불변)
```
IPassable 한 개 (예: World Pass)
├─ ① Renderable 정렬: IRenderable[] 를 Queue Layer(정수) + Z 로 Sort
└─ ② Color Override (per-fragment, 🟢 ROP): Scissor → Stencil → Depth → Blend → ColorMask
```
> ※ **두 "Layer" 구분**: **Cull Layer**(③, BitFlag, *어느 Target 이 그리나*) ≠ **Queue Layer**(①, 정수, *Pass 안 그릴 순서*).

## [전체 계층 구조] (v2)
```
PassIterator                         (= Render Hierarchy, 매 프레임 재구축)
└─ Vector<IPassable*>  passes[]      (★ Flat, 순서 SSOT, before/after = 인덱스. PassGroup 없음)
   └─ IPassable (Skybox/World/Particle/Screen/PostFx/ImGUI)
      ├─ Draw() : 입력 텍스처 → 자기 출력 텍스처 (1-in-1-out)
      ├─ GetPassResult() : Texture (Tn)
      ├─ BeforeIndex / AfterIndex : Vector 인덱스 (지역성)
      └─ 내부: ① IRenderable[] (Queue Layer+Z sort) → ② Color Override(ROP)
   ↳ 각 IRenderable 은 Target(Canvas)에 그림 (Ortho/Perspective, CullingMask 로 대상 선별)
```

## [현 엔진 대응 매핑]
| v2 개념 | 현 엔진 |
|---|---|
| `IRenderable` + `Render(Target)` | (없음) `MeshRenderer`/`PassComponent` + `MeshPassProcessor` |
| `Target`(=Canvas, Camera 폐기) | `Camera` + `RenderTarget`/`Framebuffer` (→ 통합 의도) |
| Cull Layer + CullingMask | `Camera.CullingMask & Actor.Layer` — BitFlag 일반화 |
| `IPassable` + `PassIterator`(Flat Vector) | `IRenderPassable`(stages 벡터) — 단 현재는 PassGroup/PassComponent 혼재 → Flat IPassable 로 단일화 |
| **`WorldPass : IPassable`** | **`SceneRenderer`** (거의 동일 — BeginFrame + Light 업로드 + CollectFromActor + SortMultiStage + Process). `Draw()` 로 *재배치* |
| `SkyboxPass`/`ParticlePass`/`ScreenPass`/`PostFxPass` : IPassable | `CameraStage`(skybox 수집) / `ParticleStage`(Effekseer) / `ScreenQuadStage` / `PassComponent` 체인 |
| 1-in-1-out + BeforeIndex 체인 | PostFX `PassComponent` FBO→FBO 체인 (→ Pass 자체가 텍스처 소유로) |
| Queue Layer + Z 정렬 | `MeshPassProcessor::SortMultiStage`(`RenderQueue`+depth) |
| Color Override | `Pass::RenderStateBlock` + GPU ROP |

## [용어 사전]
- **IRenderable** : 그려질 대상. `Render(Target)`.
- **Target/Canvas** : 그려지는 표면(FBO/Texture). 카메라 = View/Proj 가진 Target.
- **Cull Layer (BitFlag)** : 대상 가시성 레이어, Target CullingMask 와 AND (🔵 Unity).
- **Queue Layer (정수)** : Pass 내 그리는 순서 (🟡 RenderQueue).
- **IPassable** : 그리는 단위 인터페이스. `Draw()` + `GetPassResult()` + before/after 인덱스. 완전 함수형 1-in-1-out.
- **PassIterator** : 매 프레임 재구축되는 `Vector<IPassable*>` 를 Flat 루프 (PassGroup 폐기).

## [v2 변경 요약]
1. Pass → **`IPassable`** 인터페이스 (`Draw`/`GetPassResult`/before·after 인덱스).
2. **PassGroup + 템플릿메서드 폐기** → Flat `Vector<IPassable*>` 를 PassIterator 가 직접 루프.
3. **순서 SSOT = Vector** (heap 링크드리스트 아님, *지역성* 이유), before/after = **인덱스**.
4. **완전 함수형 1-in-1-out** (모든 Pass 각자 텍스처).
5. ❓열린: 입력 배선 채널 — **추천 A**(BeforeIndex + `Draw(Texture)`, SetBeforePass 폐기) vs B(SetBeforePass + `void Draw()`, 인덱스 폐기).
