# 렌더링 시스템 마이그레이션 계획안 (v5)

> 작성: 2026-06-23 (v5 — **범위 분리 확정**: 이번 = *렌더 아키텍처만* / 백엔드 Facade+Strategy·PSO·RT풀 = **별도 후속 프로젝트**(§7). v4 의 RHI/풀 인터페이스 6종 defer, **A-dedup + 구체 DeviceContext** 확정).
> 빌드/커밋 = **사용자**. 표기: **E**=확장 · **N**=신규 · **G**=갭 · ⚠️계약변경.

## 0. v4 → v5 변경 요약 (왜 가벼워졌나)

세션 후반 두 통찰이 범위를 갈랐다 (둘 다 모범엔진 context7 로 검증):

1. **멀티백엔드 seam 의 위치**: *고수준 `ICommandRecorder`* 가 아니라 *`DeviceContext` Facade 아래 `IGraphicsBackend` Strategy* 에 산다 — Unreal `FRHICommandList`(기록) + `FDynamicRHI`/`GDynamicRHI`(swap 백엔드), Godot `RenderingDevice`(추상) + driver(vulkan/d3d12/metal) 정통. → **고수준(IRenderable/IPassable/Processor/PassIterator)은 구체 `DeviceContext&` 만 안다**. ICommandRecorder 불요.
2. **얕은 인터페이스 정리**: `ITargetAllocator`/`IRenderTargetPool` 은 그 *형제-인터페이스* 모델의 산물이라 Facade 모델에선 seam 이 아님 → 얕음 → **defer**. (자원 생성은 미래 `IGraphicsBackend` 책임, transient 풀은 메모리 트리거 시.)

→ **이번 마이그레이션 = 렌더 *아키텍처* 만** (Material ROP → IRenderable → Flat Processor → IPassable 역할군 → PassIterator). 백엔드/PSO/풀 = 별도 후속(§7). 지금 필요한 *공짜 forward-compat* 은 이미 있음: ① gl* 격리(DeviceContext 가 유일 소유자), ② `RenderStateBlock`-as-data(PSO 디스크립터 씨앗).

> v5 가 **defer 한 것**: `ICommandRecorder` · `ITargetAllocator` · `IRenderTargetPool` · `DedicatedTargetPool` · `TargetDesc` · `PipelineStateDesc`(P2). 전부 §7 후속으로.

## 1. 모델 (확정)

### 1.1 ★ 두 레벨 순서 (D8)
"무엇이 어떤 순서로 덮어씌워지나" 를 *두 층*으로 — Unity `RenderPassEvent`+`SortingCriteria` / Unreal `EMeshPass`+sort key 정통:

| 레벨 | 결정자 | 의미 |
|---|---|---|
| **코스(coarse)** | **Pass 순서** (`PassIterator` 의 `vector<IPassable*>`) | *역할군* — 큰 그림 렌더 순서 명시 |
| **파인(fine)** | **QueueLayer**(+depth) (Pass 내부 `RenderableProcessor`) | Pass 안 IRenderable 자유 교차 |

### 1.2 축 1 — `IRenderable` (Pass 안 함께 정렬되는 drawable, D5)
```cpp
class IRenderable : public IRenderStateProvider {        // 딱 3개 (LSP-최소)
    virtual void Render(DeviceContext& rec, const Scene::Camera& cam) const = 0;   // ★ 구체 DeviceContext (D10)
    virtual int  QueueLayer() const = 0;
    // GetRenderStateBlock() <- IRenderStateProvider
};
```
> mesh-family = 이미 `MeshRenderer` 단일 경로 (`SpriteRenderer:MeshRenderer`, Text=글리프 SpriteRenderer, `CollectFromActor`가 `GetComponent<MeshRenderer>()`). ⚠️ 착수 전 live 재확인(§9). Particle/ImGui 은 *역할 Pass* (1.3).

### 1.3 축 2 — Pass = `IPassable` *하나* + 역할군 분리 (D4)
```cpp
class IPassable {                                        // 유일 Pass 인터페이스
    virtual void           Draw(DeviceContext& rec, const Texture* before) = 0;   // ★ 구체 DeviceContext (D10)
    virtual const Texture* GetPassResult() const = 0;    // = Framebuffer color attachment (D6)
    virtual void           OnResize(int w, int h) {}
    int BeforeIndex = -1;                                // 입력 Pass vector 인덱스. -1 = sceneRaw
};
// 역할군 구체 Pass: SkyboxPass / WorldPass{RenderableProcessor mProc} / ParticlePass{efk} / ImGuiPass / PostFxPass
```
`PassIterator` 는 `vector<IPassable*>` 만, `main` 은 `PassIterator` 하나만 안다.

### 1.4 ROP Facade — `IRenderStateProvider` (D7)
```cpp
struct IRenderStateProvider { virtual const Pass::RenderStateBlock& GetRenderStateBlock() const = 0; };
class  Material    : public IRenderStateProvider { Pass::RenderStateBlock mState; /* SetPass=seed */ };  // ★ 저장처
// IRenderable(mesh): GetRenderStateBlock() -> mMaterial->GetRenderStateBlock()  (facade 위임)
```
- **D9 general default**: efk/ImGui 처럼 ROP 못 꺼내면 `RenderStateBlock{}`(중립) 반환 → 순서 `QueueLayer+Z` 만으로. 실 GL state 는 라이브러리가 Render() 내부 설정 + `InvalidateStateCache` 경계.
- `RenderStateBlock` 은 깨끗한 데이터(이미 Depth/Cull/Blend/Stencil POD) = **PSO 디스크립터 씨앗**(§7 후속이 그대로 재사용).

### 1.5 Flat `RenderableProcessor` + A-dedup (D5/D12)
```cpp
class RenderableProcessor {                              // mesh 특수 0
    struct Entry { const IRenderable* r; int queueLayer; float depth; };   // depth 는 collect 때 카메라로 동봉
    std::vector<Entry> mItems;
    void Submit(const IRenderable* r, float viewDepth);
    void Sort();                                         // stable_sort: QueueLayer asc -> (투명)depth back-to-front
    void Process(DeviceContext& rec, const Scene::Camera& cam) {           // §0.5 flat (per-renderable 자가발행)
        rec.InvalidateStateCache();
        for (auto& e : mItems) { rec.ApplyRenderStateBlock(e.r->GetRenderStateBlock()); e.r->Render(rec, cam); }
    }
};
```
> **A-dedup (D12)**: 배치 최적화(직전과 같은 program/state skip)는 *루프가 아니라* `DeviceContext` 캐시(`mBoundProgram`/`mLast`, D-RS-1 연장)가 흡수 — Unity SRP Batcher(persistent buffer, "material 안 바뀌면 state 변경 회피") + Godot `UniformSetCacheRD`(redundant bind skip) 정통. 잎/루프/인터페이스는 §0.5 flat 유지.

### 1.6 `DeviceContext` 구체 유지 (D10)
gl* 의 **유일 소유자**(GL 격리 불변식) + A-dedup 캐시. 고수준은 이 구체를 직접 받음. 멀티백엔드(IGraphicsBackend Strategy)는 §7 후속.

## 4. Phase 계획 (in-place, 5단계 — Phase 1 기반인터페이스 제거됨)

### Phase 1 — Material RenderStateBlock 보유 + `IRenderStateProvider` [E+N, D7]
- **N** `IRenderStateProvider`. **E** `Material : IRenderStateProvider` (`mState` 멤버, `SetPass`=seed). 소비처 `mesh_pass_processor.cpp` 의 `DefaultRenderStateBlockOf(material->GetPass())` → `material->GetRenderStateBlock()`.
- 검증: 빌드 GREEN + 육안(seed=기존 도출 무회귀; healthbar/shadow 알파 핫스팟).

### Phase 2 — `IRenderable` + Flat `RenderableProcessor` (A-dedup) [E, D5/D8-파인/D12]
- **E** `IRenderable : IRenderStateProvider {Render(DeviceContext&,Camera&)/QueueLayer}`. `MeshRenderer` 충족(잎 자가발행 = UseProgram+UBO+sampler+draw).
- **E** `MeshPassProcessor`→`RenderableProcessor`(IRenderable* 제네릭, §0.5 flat). 배치는 DeviceContext 캐시 dedup(필요 시 `UseProgram`/UBO 멱등 가드 추가).
- 검증: 빌드 GREEN + 육안(mesh/sprite/text 출력·순서 동일). `stable_sort` 유지.

### Phase 3 — `IPassable` 계약 + 역할군 Pass 통합 [E⚠️→통합, D2/D3/D4] — *한 Pass씩 육안*
- **E⚠️** `IRenderPassable`→`IPassable`(`Draw(DeviceContext&, const Texture*)`/`GetPassResult()->const Texture*`/`BeforeIndex`).
- **E** `WorldPass:IPassable{RenderableProcessor}` ← `SceneRenderer`+`CameraStage`. `SkyboxPass` / `ParticlePass`(←ParticleStage,efk) / `ImGuiPass`(←main ImGui) / `PostFxPass`(←PassComponent+ScreenQuadStage).
- 검증: **Pass 하나 전환마다** 빌드 GREEN + 육안.

### Phase 4 — `PassIterator` 모듈화 + main 배선 + DebugPassIndex [E, D8-코스]
- **N** `PassIterator{Add/Execute(DeviceContext&,RenderTarget&)/Resize/DebugPassIndex}`. **E** `main.cpp`: `mStages`→`mPassIterator` 하나. 코스 순서=역할군, 각 `BeforeIndex` 배선. ImGui 직접 호출 → ImGuiPass.
- 검증: 빌드 GREEN + 육안(평소 동일 + 디버그 키).

### Phase 5 — 정리/네이밍/문서 [E]
- 구 심볼(`SceneRenderer`/`CameraStage`/`ScreenQuadStage`/`MeshPassProcessor`/`IRenderPassable`) 정리, `doc/diagrams/` 갱신, 메모리/CLAUDE.md.

## 6. Task 때 재검토(설득) 지점
- **SkyboxPass 독립 vs WorldPass skybox-queue**: 역할군 가독성이면 독립.
- **ParticlePass/ImGuiPass 내부 IRenderable 사용 여부**: 역할 Pass 라 efk/ImGui 직접 호출이면 IRenderable 불요(과할 수 있음).
- **RenderableProcessor 공개 폭**: WorldPass 멤버로 둘 때 API 최소화(Submit/Sort/Process).
- **depth 키 계산 위치**: QueueLayer 정수, within-layer depth 는 카메라 필요 → **collect(Submit) 시점 동봉** (WorldPass 가 카메라 앎). IRenderable 은 3 메서드 유지.
- **A-dedup 구현 깊이**: 우선 UseProgram dedup(mBoundProgram 이미 보유)만, FrameBlock/sampler 멱등 가드는 프로파일 후. (성능 회귀 측정되면 추가)

## 7. 후속 프로젝트 — 멀티백엔드 (별개, 이번 범위 밖)

> 이번 마이그레이션이 끝난 *뒤* 착수. 이번이 깔아둔 토대(gl* 격리 + RenderStateBlock-as-data) 위에서 비파괴로 얹힘.

**목표 형태 (Bridge: 추상 Facade ↔ 구현 Strategy)** — Unreal `FRHICommandList`+`FDynamicRHI`/`GDynamicRHI`, Godot `RenderingDevice`+driver 정통:
```cpp
struct PipelineStateDesc { const Pass::RenderStateBlock* State; const Program* Shader; GLuint VtxFormat; };  // PSO 디스크립터 (Godot render_pipeline_create 인자 대응)

class IGraphicsBackend {                       // swap 백엔드 Strategy (FDynamicRHI / RenderingDevice driver)
    virtual void BindPipelineState(const PipelineStateDesc&) = 0;   // GL=명령형+dedup / Vulkan=GetOrCreatePSO+bind
    virtual Texture* CreateTexture(...) = 0; virtual Framebuffer* CreateFramebuffer(...) = 0;   // 자원 생성도 백엔드
    virtual void Draw(...) = 0; ...
};
// DeviceContext(Facade): mBackend 보유 + 상태캐시/A-dedup. 고수준은 여전히 구체 DeviceContext& (무변).
// OpenGLBackend / VulkanBackend / MetalBackend : IGraphicsBackend. (Godot 선례 - GL 은 특별/별도 driver 가능)
```
- PSO: D3D12/Vulkan/Metal 공통 "GPU state 묶음"(Unreal "universal term"). `Pass::RenderStateBlock`+`Program`+vtxFormat 이 디스크립터. GL 은 명령형으로 unpack+dedup, 모던 API 는 ahead-of-time PSO 생성+캐시(히치 회피).
- `IRenderTargetPool`(Dedicated↔Transient aliasing) — 메모리 트리거 시. 🔵 Unreal `r.RDG.TransientAllocator`, Unity RTHandle.
- **진입 조건**: 실제 2번째 백엔드 착수 시 (그때 seam 모양이 드러남). Slang 이 셰이더 크로스컴파일을 이미 해결해 둔 게 큰 토대.

## 8. 요약
- **범위**: 이번 = 렌더 *아키텍처* (Material ROP → IRenderable → Flat Processor(A-dedup) → IPassable 역할군 → PassIterator). 고수준은 **구체 DeviceContext&**. 백엔드/PSO/풀 = §7 후속.
- **2레벨 순서**(D8) · **IPassable 하나+역할군**(D4) · **IRenderable mesh-family**(D5) · **ROP Material+Facade**(D7) · **A-dedup**(D12).
- **defer**(v5): ICommandRecorder · ITargetAllocator · 풀 · TargetDesc · PipelineStateDesc → 후속.
- 큰 작업 = Phase 3(역할군 Pass 통합) + Phase 4(PassIterator).
- §1 확정 → Phase 1(Material ROP) 착수 가능.
