## 3. 컴포넌트별 정확한 사보타지 위치

### 컴포넌트 A — CaptureGLState (3 사보타지)

**대상 파일**: [src/diagnostics/gl_state_fields.cpp](../../src/diagnostics/gl_state_fields.cpp) — `CaptureGLState()` 함수.
**ctest 필터**: `-R "CaptureGLState|fresh fixture"`
**결과 기록**: [test-quality-drill/gl_state_capture.md](test-quality-drill/gl_state_capture.md)

#### A-1. VAO ↔ Program swap

**변경**:
```cpp
// Before
glGetIntegerv(GL_VERTEX_ARRAY_BINDING, &tmp); f.vao     = static_cast<GLuint>(tmp);
glGetIntegerv(GL_CURRENT_PROGRAM,      &tmp); f.program = static_cast<GLuint>(tmp);

// After (사보타지 — 두 줄 swap)
glGetIntegerv(GL_VERTEX_ARRAY_BINDING, &tmp); f.program = static_cast<GLuint>(tmp);
glGetIntegerv(GL_CURRENT_PROGRAM,      &tmp); f.vao     = static_cast<GLuint>(tmp);
```

**예상**: "fresh fixture default" + "VAO 바인딩 후 fields.vao 반영" 둘 다 FAIL.

#### A-2. 텍스처 unit loop 줄임

**변경**:
```cpp
// Before
for (int i = 0; i < 16; ++i) {

// After (사보타지)
for (int i = 0; i < 1; ++i) {
```

**예상**: fresh fixture는 모든 unit이 0이라 우연 통과 가능 → **blind spot 가능성 높음**. 잡히지 않으면:
1. test_gl_state_capture.cpp에 다음 케이스 추가:
   ```cpp
   TEST_CASE("CaptureGLState — unit 5에 텍스처 바인딩 후 캡처", "[diagnostics][capture]") {
       SJH::test::GLContextFixture ctx;
       GLuint tex = 0;
       glGenTextures(1, &tex);
       glActiveTexture(GL_TEXTURE5);
       glBindTexture(GL_TEXTURE_2D, tex);
       auto f = CaptureGLState();
       REQUIRE(f.texture_2d_per_unit[5] == tex);
       glDeleteTextures(1, &tex);
   }
   ```
2. 다시 사보타지 → ctest → 이번엔 잡힘.

#### A-3. active_texture 복원 누락

**변경**:
```cpp
// Before
GLint saved_active = 0;
glGetIntegerv(GL_ACTIVE_TEXTURE, &saved_active);
for (int i = 0; i < 16; ++i) {
    glActiveTexture(GL_TEXTURE0 + i);
    glGetIntegerv(GL_TEXTURE_BINDING_2D, &tmp);
    f.texture_2d_per_unit[i] = static_cast<GLuint>(tmp);
}
glActiveTexture(static_cast<GLenum>(saved_active));   // ← 이 라인

// After (사보타지 — 마지막 줄 삭제 또는 주석)
//glActiveTexture(static_cast<GLenum>(saved_active));
```

**예상**: "부수효과 0 — active_texture 변하지 않음" FAIL.

### 컴포넌트 B — Diff (3 사보타지)

**대상 파일**: [test/support/gl_state_snapshot.cpp](../../test/support/gl_state_snapshot.cpp).
**ctest 필터**: `-R "Diff|ToString"`
**결과 기록**: [test-quality-drill/diff.md](test-quality-drill/diff.md)

#### B-1. 항상 "(no change)" 반환

**변경**: `Diff` 함수의 첫 줄 (변수 선언 직후) 에 추가:
```cpp
std::string Diff(const GLStateSnapshot& A, const GLStateSnapshot& B)
{
    return "(no GL state change)\n";   // ← 사보타지 (모든 logic dead code)
    // ... 나머지 기존 코드 ...
}
```

**예상**: 변화 비교 케이스 다수 FAIL — "Diff — handle 변화", "enum 변화", "element_buffer + VAO=0 EBO 주석", "texture unit 변화", "attribute slot 변화", "attribute size 변화".

#### B-2. DiffField에서 condition 제거

**변경**:
```cpp
// Before
template <typename T>
void DiffField(std::string& out, const char* name, const T& a, const T& b)
{
    if (a != b) {
        out += fmt::format("  {}: {} → {}\n", name, a, b);
    }
}

// After (사보타지 — if 제거)
template <typename T>
void DiffField(std::string& out, const char* name, const T& a, const T& b)
{
    out += fmt::format("  {}: {} → {}\n", name, a, b);
}
```

**예상**: "Diff — 동일 snapshot은 '(no GL state change)'" FAIL (출력이 비지 않음) + "attribute 모든 필드 동일하면 변화 출력 안 됨".

#### B-3. before/after swap

**변경**:
```cpp
// Before
const auto& a = A.fields;
const auto& b = B.fields;

// After (사보타지)
const auto& a = B.fields;   // swap
const auto& b = A.fields;   // swap
```

**예상**: "Diff — handle 변화는 raw 정수" 케이스가 substring "3"과 "5"를 각각 검사하므로 swap해도 둘 다 매치 → **잡히지 않을 가능성 높음**. 잡히지 않으면:
- 케이스 강화: `REQUIRE_THAT(d, ContainsSubstring("3 → 5"));` (정확한 방향) 추가
- `REQUIRE_FALSE(d.find("5 → 3") != std::string::npos);` (역방향 없음) 추가

### 컴포넌트 C — SymbolicName (4 사보타지, N11 포함)

**대상 파일**: [src/diagnostics/gl_state_fields.cpp](../../src/diagnostics/gl_state_fields.cpp) — `SymbolicName(GLenum)` 함수.
**ctest 필터**: `-R "SymbolicName|FieldsToString"`
**결과 기록**: [test-quality-drill/symbolic_name.md](test-quality-drill/symbolic_name.md)

#### C-1. hex fallback → 사전 첫 entry 강제

**변경**:

```cpp
// Before (hex fallback 부분)
static thread_local char buf[16];
snprintf(buf, sizeof(buf), "0x%04X", static_cast<unsigned>(e));
return buf;

// After (사보타지)

```

**예상**: "SymbolicName 미적중 → hex fallback" FAIL — `Equals("0xDEAD")` 깨짐.

#### C-2. lowercase 결과

**변경**: switch case의 string literal을 lowercase로:
```cpp
// Before
case GL_LESS: return "GL_LESS";

// After
case GL_LESS: return "gl_less";
```

**예상**: "SymbolicName 사전 적중" + "사전 boundary — depth_func 모든 8개" FAIL.

#### C-3. case GL_LESS 삭제

**변경**: `case GL_LESS: return "GL_LESS";` 라인 통째로 삭제 → fallthrough로 hex 출력.

**예상**: 위 두 케이스 모두 FAIL — `Equals("GL_LESS")` 자리에 `Equals("0x0201")` 차이.

#### C-4. case GL_FLOAT 삭제 (N11 회귀)

**변경**: `case GL_FLOAT: return "GL_FLOAT";` 라인 삭제.

**예상**: [test_gl_state_log.cpp](../../test/test_gl_state_log.cpp) "FieldsToString — attribute enabled 시 size/type/stride/vbo 출력" FAIL — `attrib[0]: vec3 0x1406, ...` 으로 hex 누설, `ContainsSubstring("GL_FLOAT")` 깨짐.

### 컴포넌트 E — Smell Linter (3 사보타지, ctest 없이 수동)

**대상 파일**: [scripts/check_test_smells.py](../../scripts/check_test_smells.py).
**검증**: 수동 실행 — `python3 scripts/check_test_smells.py test/`
**결과 기록**: [test-quality-drill/smell_linter.md](test-quality-drill/smell_linter.md)

> **차이점**: ctest 케이스 단언이 없으므로 *baseline 출력과 사보타지 출력의 직접 비교*. 사전에 `python3 scripts/check_test_smells.py test/ > /tmp/linter_baseline.txt` 저장.

#### E-1. STATIC_REQUIRE alternation 삭제 (N10 회귀)

**변경**:
```python
# Before
ASSERT_RE = re.compile(
    r'\b(REQUIRE|CHECK|REQUIRE_FALSE|CHECK_FALSE|REQUIRE_THROWS(?:_AS|_WITH|_MATCHES)?|'
    r'CHECK_THROWS(?:_AS|_WITH|_MATCHES)?|SUCCEED|REQUIRE_THAT|CHECK_THAT|'
    r'STATIC_REQUIRE(?:_FALSE)?|STATIC_CHECK(?:_FALSE)?)\s*\('   # ← 이 줄 삭제
)

# After (사보타지 — STATIC_* alternation 통째로 삭제)
ASSERT_RE = re.compile(
    r'\b(REQUIRE|CHECK|REQUIRE_FALSE|CHECK_FALSE|REQUIRE_THROWS(?:_AS|_WITH|_MATCHES)?|'
    r'CHECK_THROWS(?:_AS|_WITH|_MATCHES)?|SUCCEED|REQUIRE_THAT|CHECK_THAT)\s*\('
)
```

**예상**: `python3 scripts/check_test_smells.py test/` → test_glfw_utils.cpp의 6개 TEST_CASE에 R1 false positive (현재 0 warnings → 6 warnings).

#### E-2. REQUIRE alternation 삭제

**변경**: ASSERT_RE에서 `REQUIRE|` 제거 (가장 흔한 매크로 미감지).

**예상**: 거의 모든 test 파일에서 R1 false positive 폭증 (test_buffer, test_program_uniforms, test_gl_state_capture, test_gl_state_log, test_gl_state_snapshot 등).

#### E-3. TEST_CASE_RE tag capture 제거

**변경**:
```python
# Before
TEST_CASE_RE = re.compile(
    r'TEST_CASE\s*\(\s*"(?P<name>[^"]*)"\s*(?:,\s*"(?P<tags>[^"]*)")?\s*\)\s*\{'
)

# After (사보타지 — 두 번째 인자 capture 통째로 삭제)
TEST_CASE_RE = re.compile(
    r'TEST_CASE\s*\(\s*"(?P<name>[^"]*)"\s*\)\s*\{'
)
```

**예상**: 거의 모든 TEST_CASE가 매치 안 됨 (TEST_CASE는 두 번째 인자 있는 게 보통이라 정규식 자체가 fail) → R1/R2/R3 모두 0건. *false negative*: smell이 실제로 있어도 탐지 안 됨.

> **이 사보타지는 R3 false positive가 아니라 *전체 탐지 실패*** — TEST_CASE_RE가 더 이상 매치 안 함. 검증: 사보타지 후 출력에 `0 warnings`만 보일 것 → **이게 진짜 위험한 false negative**.

## 4. 결과 기록 템플릿

각 사보타지 후 해당 `.md` 파일의 표를 다음과 같이 갱신:

```markdown
| # | 사보타지 | 적용 위치 | 예상 잡는 케이스 | 실제 잡힌 케이스 | 드릴 날짜 |
|--:|---|---|---|---|---|
| 1 | ... | ... | ... | **`fresh fixture default` (예상 일치 ✓)<br>`VAO 바인딩 후 fields.vao 반영` (예상 일치 ✓)** | 2026-05-09 |
```

### 표기 컨벤션

| 표기 | 의미 |
|---|---|
| `(예상 일치 ✓)` | 예상한 케이스가 그대로 FAIL |
| `(추가 ✓)` | 예상 외 케이스도 추가로 FAIL |
| `(blind spot ✗ — 추가 케이스 필요)` | 예상한 케이스가 잡지 못함 |
| `(모두 PASS — 케이스 추가 필요)` | 사보타지 적용했는데 모든 테스트 PASS |
| `(추가 후 catch ✓)` | 케이스 추가 후 재드릴해서 catch됨 |

### 컴포넌트별 결과 노트 갱신

각 컴포넌트 파일의 **결과 노트** 섹션:

```markdown
## 결과 노트 (2026-05-09 드릴)

- 예측 정확도: 3/3 정확 일치 (또는 X/Y)
- 발견된 blind spot: A-2 — fresh fixture만으로는 unit loop 줄임 사보타지 잡지 못함
- 추가한 케이스: test_gl_state_capture.cpp "CaptureGLState — unit 5에 텍스처 바인딩 후 캡처"
- 후속 작업: 케이스 추가 후 A-2 재드릴 → 잡힘 ✓
```

## 6. 안전장치

- **드릴 도중 본 plan 외 파일 수정 금지** — 결과 추적 어려워짐.
- **`git stash --include-untracked`** 로 미커밋 변경 보호 (드릴 중 다른 작업 충돌 방지).
- **각 사보타지 사이클 후 `git status`** 로 의도하지 않은 잔여 변경 확인.
- **ctest 출력은 `/tmp/drill_*.txt` 로 저장** — 사후 비교 가능.
- **사보타지 *적용*과 *복원*은 항상 짝**: `$EDITOR ... && git checkout -- ...` 한 사이클로 묶어서 진행. 사보타지 두 개 이상을 동시에 적용하지 말 것 (효과 분리 안 됨).
