## 🏛 반드시 따라야 할 아키텍처 패턴

### 1. leaf Playable = `PlayableBase` 상속, OnUpdate 만 필수
`SpriteSequencePlayable` 가 본보기 — OnUpdate(dt) override + paused_/finished_/elapsed_/isLoop_ 베이스 활용. OnPlay/OnStop 은 *외부 리소스 lifecycle 관리 필요할 때만* override (FMOD/Effekseer 는 필요, SpriteSequence 는 불필요).

```cpp
class FmodPlayable : public SJH::Playable::PlayableBase {
  public:
    FmodPlayable(FMOD::System* sys, FMOD::Sound* sound) : sys_(sys), sound_(sound) {}

  protected:
    void OnPlay() override {
        sys_->playSound(sound_, nullptr, false, &channel_);
    }
    void Pause() override {                          // ← IPlayable 의 Pause 직접 override
        SJH::Playable::PlayableBase::Pause();        //   (base 가 paused_ = true)
        if (channel_) channel_->setPaused(true);     //   + FMOD 도 정지
    }
    void OnStop() override {
        if (channel_) { channel_->stop(); channel_ = nullptr; }
    }
    void OnUpdate(float /*dt*/) override {
        if (!channel_) return;
        bool playing = false;
        channel_->isPlaying(&playing);
        if (!playing && !isLoop_) finished_ = true;
    }

  private:
    FMOD::System* sys_;       // 외부 owner
    FMOD::Sound*  sound_;     // 외부 owner (AudioSystem 캐시)
    FMOD::Channel* channel_ = nullptr;   // 자체 owner — Play 시 받음
};
```

### 2. *Resource Owner* 와 *Playable* 분리
**Sound / Effect 자원** = 별도 System (AudioSystem / VFXSystem) 이 owner — 캐시. **Playable 인스턴스** = 자원 raw ptr 만 보유 + 자기 핸들 (Channel/Handle/EventInstance) 만 자체 소유. `PhysicsSystem` + `Components::Physics(BoxBody/CircleBody)` 정통 패턴 그대로.

```cpp
// AudioSystem (선택) — FMOD::System 싱글톤 + Sound 캐시
class AudioSystem {
  public:
    void Init();
    void Shutdown();
    FMOD::System* GetSystem() { return system_; }
    FMOD::Sound*  LoadSound(const std::string& path);   // 캐시
    void Update(float dt);   // system_->update() 매 프레임
  private:
    FMOD::System* system_ = nullptr;
    std::unordered_map<std::string, FMOD::Sound*> soundCache_;
};
```

### 3. game_deps 의존 leaf = **Client 거주** 강제
spec §1.5 + IPlayable spec §6.2 + memory `next_work_playable` — `src/playable/` 안에 절대 추가 금지. `SJH::playable` 코어 모듈의 *game_deps 의존 0* 유지.

### 4. POST_BUILD dll copy = 이미 wired
`_MyApp_/CMakeLists.txt` 가 `game_deps` link 시점에 `$<TARGET_FILE:fmod>` copy 가 자동. 새 leaf 추가하면서 *POST_BUILD 추가 작업 0*. (`fmod_game_deps_auto_join` memory)

### 5. Composite + leaf 결합 사용 (T5 의 시각 검증 핵심)
M3.5 잔여 = *Composite (Sequence/Parallel) 의 실 사용처 시각 검증*. T5 의 muzzle 시퀀스가 정확히 이 검증을 수행 — 사용자 확인 시점에 "Sequence + Parallel 계층 중첩이 의도대로 동작" 명시.

### 6. Tweeny 함정 (T4 도입 시)
`tweeny_step_overload_trap` memory — `step(int32_t ms)` 와 `step(float ratio)` 두 오버로드. **`step(float)` 에 ms 값을 넘기면** 누적 ratio 가 0.001 같은 분수가 되어 *양 끝 깜빡임 폭주*. TweenPlayable 의 OnUpdate 는 `step(int32_t(dt * 1000.0f))` 명시.
