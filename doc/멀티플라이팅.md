# 멀티 라이팅(Multi-Lighting) 정리 — `exercise8_win` → `chapter8` 변경 노트

`apps/exercise8_win/main.cpp`(단일 광원 베이스)에서 `apps/chapter8/main.cpp`(다중 광원 + 진단 모듈)로 넘어오면서 무엇이 어떻게 바뀌었는지를 모듈 / 카테고리 / 기능별로 정리한다.

- **베이스 버전**: `exercise8_win` — Phong 단일 광원 1개, 디퓨즈/스페큘러 맵, 광원 표시용 피라미드 1개. 진단 코드 없음.
- **확장 버전**: `chapter8` — 방향광 1 + 점광원 N개 + 스포트라이트 1, 거리 감쇠, 소프트 에지, 유니폼 헬퍼, GL 진단 모듈 풀세트.

## 1. 라이팅 모델 — 단일 광원 → 3종 광원 합성

### 1.1 광원 타입 (C++ 구조체)

| 항목 | exercise8_win | chapter8 |
|---|---|---|
| 광원 구조체 | `Light` 1종 (position, ambient, diffuse, specular) | `Light`(레거시·미사용), `DirLight`, `PointLight`, `SpotLight` 4종 |
| 광원 인스턴스 | `Light m_light;` 1개 | `DirLight m_dirLight; PointLight m_pointLights[2]; SpotLight m_spotLight;` |
| 광원 개수 매크로 | 없음 | `#define NUM_POINT_LIGHTS 2` (C++/GLSL 양쪽에서 동일하게 정의) |

- `DirLight`: `direction`, `ambient/diffuse/specular` — 위치가 없는 전역 평행광(태양광).
- `PointLight`: `position`, **`c1`, `c2`** (거리 감쇠 계수), `ambient/diffuse/specular`.
- `SpotLight`: `position`, `direction`, **`cutOff`, `outerCutOff`** (안/바깥 원뿔 코사인 값), `c1`, `c2`, `ambient/diffuse/specular`.

### 1.2 프래그먼트 셰이더 구조 (`basic_lighting_fs.glsl`)

- exercise 버전은 사실상 `Light light` 하나로 Phong 한 번 계산.
- chapter8 버전은 **합산 파이프라인**:
  ```glsl
  result  = CalcDirLight(dirLight, ...);                 // 1) 방향광
  for (i in NUM_POINT_LIGHTS) result += CalcPointLight(pointLights[i], ...);  // 2) 점광원 N개
  result += CalcSpotLight(spotLight, ...);               // 3) 스포트라이트
  fragColor = vec4(result, 1.0);
  ```
- GLSL은 동적 배열이 불가능하므로 `uniform PointLight pointLights[NUM_POINT_LIGHTS];` 처럼 컴파일 타임 상수 크기 배열을 쓴다.
- 공통 항(ambient/diffuse/specular)을 `CalcAmbient / CalcDiffuse / CalcSpecular` 헬퍼로 분리하고, 각 광원 함수(`CalcDirLight`, `CalcPointLight`, `CalcSpotLight`)는 **광원 방향(lightDir) 산출 방식**과 **감쇠/강도 곱**만 다르게 한다.
  - `CalcDirLight`: `lightDir = normalize(-light.direction)`, 감쇠 없음.
  - `CalcPointLight`: `lightDir = normalize(light.position - fragPos)`, 거리 감쇠 곱.
  - `CalcSpotLight`: 점광원 + 소프트 에지(intensity) + 거리 감쇠를 ambient/diffuse/specular 모두에 곱.

### 1.3 거리 감쇠 (Attenuation)

- 추가된 공식: `attenuation = 1 / (1 + c1·d + c2·d²)` — `CalcAttenuation(vec2(c1,c2), d)`.
- 셰이더 주석에 커버 거리별 권장 `c1/c2` 테이블이 들어있음(거리 7 → 0.7/1.8 … 3250 → 0.0014/0.000007). 현재 코드는 거리 50 기준값 `c1=0.09, c2=0.032`를 사용.

### 1.4 스포트라이트 소프트 에지

- `CalcSoftEdge(theta, phi, gamma)`:
  - `theta = dot(lightDir, normalize(-light.direction))` — 프래그먼트가 원뿔 축에서 얼마나 벗어났는지(코사인).
  - `theta > cutOff` → 강도 1 (안쪽), `theta < outerCutOff` → 강도 0 (바깥), 그 사이는 `(theta - gamma)/(phi - gamma)` 선형 페이드.
- C++ 쪽에서 `cutOff = cos(radians(12.5°))`, `outerCutOff = cos(radians(15.5°))` 로 설정.

## 2. 광원 애니메이션 & 배치 — `render()`

| 항목 | exercise8_win | chapter8 |
|---|---|---|
| 방향광 | 없음 | `m_dirLight.direction = (-0.2, -1.0, -0.3)` 고정, 약한 ambient |
| 점광원 궤도 | 광원 1개가 `sin/cos(currentTime*0.5)` 로 작은 원 운동 | `NUM_POINT_LIGHTS`개가 **위상차(`kOrbitPhaseStep = 2π/N`)를 두고** 원궤도, 광원마다 높이(y)도 다르게 (`0.25 + 0.4*i`) |
| 스포트라이트 | 없음 | **카메라에 부착** — `position = eye`, `direction = center - eye` (손전등 효과) |
| 광원 표시용 피라미드 | `shader_programs[2]`로 광원 위치에 **1개** 그림 | `NUM_POINT_LIGHTS`개를 루프로 그림. projection/view/color는 루프 밖에서 1회만 설정(`modelLoc` 캐시) |
| 머티리얼 shininess | 셰이더에 하드코딩(또는 미사용) | C++ `Material::shininess = 32.0f` 로 유니폼 전달 |

- `M_PI`는 `vmath.h`가 `_USE_MATH_DEFINES`와 함께 `<math.h>`를 포함해 제공됨(크로스 플랫폼 주의).

## 3. 머티리얼 / 텍스처 유닛 관리

### 3.1 `Material` 구조체 확장

| 필드 | exercise8_win | chapter8 |
|---|---|---|
| `diffuseTexture` (GL 핸들) | ✅ | ✅ |
| `specularTexture` (GL 핸들) | ✅ | ✅ |
| `diffuseUnit` (이미지 유닛 번호) | ❌ | ✅ (`1` = `GL_TEXTURE1`) |
| `specularUnit` | ❌ | ✅ (`2` = `GL_TEXTURE2`) |
| `shininess` | ❌ | ✅ (`32.0f`) |

### 3.2 “핸들 vs 유닛 번호” 분리

- 핵심 개념: `sampler2D` 유니폼에는 **텍스처 객체 핸들이 아니라 텍스처 이미지 유닛 번호**를 넣어야 한다. exercise 버전은 `glUniform1i(..., 1)` / `glActiveTexture(GL_TEXTURE1)`를 손으로 맞췄지만, chapter8은 이 한 쌍을 헬퍼로 묶었다.
  - `UniformsSetMaterial(program, "material", mat)` → `material.diffuse`에 `mat.diffuseUnit`, `material.specular`에 `mat.specularUnit`, `material.shininess` 전달.
  - `BindMaterialTextures(mat)` → `glActiveTexture(GL_TEXTURE0 + mat.diffuseUnit); glBindTexture(...)` — 셰이더에 알려준 것과 **같은 유닛**에 실제 텍스처를 바인딩.
- 즉 “셰이더에 번호를 알려주는 쪽”과 “그 번호에 텍스처를 거는 쪽”이 항상 한 데이터(`Material`)에서 나오므로 어긋날 일이 없다.

## 4. 유니폼 설정 — 인라인 호출 → 구조체 단위 헬퍼

exercise 버전(`render()`)은 광원 필드마다 `glGetUniformLocation` + `glUniform3fv`를 한 줄씩 직접 호출했다. chapter8은 구조체별 헬퍼로 묶어 반복/오타를 줄였다.

- `static GLint UniformLoc(program, name)` — `glGetUniformLocation` 래퍼. **location < 0 이면 `diag::UniformDiagnostics::NotifyMissing(program, name)`** 호출 → 누락된 유니폼 이름을 진단 로그로 알려줌.
- `UniformsSetDirLight(program, prefix, light)` — `prefix + ".direction/.ambient/.diffuse/.specular"`.
- `UniformsSetPointLight(program, prefix, light)` — 위 + `.c1/.c2`.
- `UniformsSetStopLight(program, prefix, light)` — (스포트라이트) position/direction/cutOff/outerCutOff/c1/c2/ambient/diffuse/specular 전부. *(함수명이 `Stop`인 건 오타 — 의미는 SpotLight)*
- `UniformsSetMaterial(program, prefix, material)` — `.diffuse(int unit)/.specular(int unit)/.shininess(float)`.

배열 유니폼 이름은 `std::stringstream`으로 `"pointLights[" << i << "]"` 처럼 포매팅해서 `UniformsSetPointLight`에 prefix로 넘긴다.

> 참고: 박스 그리기에서 `model/view/projection/objectColor/viewPos`는 아직 인라인 `glGetUniformLocation` 그대로다. 라이트/머티리얼만 헬퍼화됨.

## 5. 진단(Diagnostics) 모듈 — chapter8에서 신규 도입

`src/diagnostics/` 의 3개 헤더를 `namespace diag = SJH::Diagnostics;` 로 끌어쓴다. exercise 버전엔 전혀 없던 레이어. `// diag::` 주석으로 표시된 줄이 전부 진단 코드.

| 헤더 | 역할 | 대표 호출 |
|---|---|---|
| `diagnostics/gl_log.h` | 셰이더/프로그램 객체 검증 | `GLObjectLog::CheckShaderCompile`, `CheckProgramLink`, `CheckProgramValidate`, `CheckExpectedAttributes`, `CheckExpectedUniforms`, `InvalidateProgramCache` / `GLDebug::CheckGL*`(BindVertexArray, BindBuffer, BufferData, VertexAttribPointer, EnableVertexAttribArray …) |
| `diagnostics/gl_state_log.h` | 현재 GL 상태 덤프 | `GLStateLog::Dump("after startup()")`, `Dump("render(): before box draw")` |
| `diagnostics/uniform_diagnostics.h` | 누락 유니폼 추적 (program 핸들 키로 캐시) | `UniformDiagnostics::NotifyMissing`, `UniformDiagnostics::Invalidate` |

도입 포인트:

1. **`compile_shader()`** — VS/FS 컴파일 직후 `CheckShaderCompile`, 링크 직후 `CheckProgramLink`. 링크 실패 시 location이 전부 무효해지므로 필수.
2. **`startup()`** — VAO/VBO/EBO 생성·바인딩·`glVertexAttribPointer` 호출마다 `GLDebug::Check*` 로 즉시 에러 감지. 마지막에:
   - `CheckExpectedAttributes(prog[1], {"pos","texCoord","normal"}, "basic_lighting")` — 정적 attribute 존재 확인 (vertex color는 라이팅 셰이더 미사용).
   - `CheckExpectedUniforms(prog[1], {"model","view","projection","viewPos","objectColor","material.diffuse","material.specular","material.shininess"}, ...)` — **정적 이름만** 검증. 동적 이름(`dirLight.*`, `pointLights[i].*`, `spotLight.*`)은 `render()`의 `UniformLoc → NotifyMissing` 경로가 잡음.
   - `prog[2]`(simple_color)도 `{"pos"}` / `{"model","view","projection","color"}` 검증.
   - `GLStateLog::Dump("after startup()")`.
3. **`render()`** — `static bool s_dumpedRenderState` 가드로 **첫 프레임에 한 번만** `CheckProgramValidate("basic_lighting@frame0")` + `GLStateLog::Dump("render(): before box draw")`. 매 프레임 스팸 방지.
4. **`shutdown()`** — 같은 `GLuint` 핸들이 재발급될 때 stale 캐시 결과를 막기 위해 모든 프로그램에 대해 `GLObjectLog::InvalidateProgramCache` + `UniformDiagnostics::Invalidate`.

## 7. 크로스 플랫폼 / 빌드 관련

- chapter8은 `#define MAC_WINE_TEST` → `init()`에서 `info.majorVersion = 4; info.minorVersion = 1;` 강제 (GL 4.1 = macOS 상한 / Wine 검증 호환). exercise8_win은 해당 `#define`이 주석 처리됨.
- 셰이더는 모두 `#version 410 core` (430 주석으로만 남김) — GL 4.1 호환 유지.
- `<sstream>`, `<string>` 추가 — 배열 유니폼 이름 포매팅용.
- 진단 모듈은 `src/diagnostics/` (헤더 온리) → chapter8 빌드 시 include 경로에 잡힘.
